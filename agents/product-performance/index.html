Data notes

  • Synthetic data from a seeded Python script, for a fictional brand. Each region has a story planted in it for the agent to find.
  • vs LY compares the same fiscal weeks last year (364 days earlier, same weekdays).
  • Weeks of supply = units on hand at the end of the latest week ÷ average weekly units sold over the last 4 weeks. Inventory is held at region level, so it ignores the channel filter.
  • New customer = first purchase with the brand; returning = everyone else. Each new customer is one first order, so orders from returning customers = orders − new customers; that counts orders, not people. Generations: Gen Z (born 1997–2012), Millennial, Gen X, Boomer. The Gen Z index compares a family's Gen Z share of new customers with the brand's (100 = same).
  • Products new this year have no last-year sales; they show as new and are left out of “families up vs LY”.
  • Thresholds, channels, currency and the fiscal calendar all come from the region's config file.
  • The agent works through four tools (sales, trend, inventory, customers) that run live on this data. The chatbot answers the suggested questions, and any typed question that matches one of them; other typed questions get a demo note, because this public page isn't connected to a language model. The tool calls behind each answer run in your browser, and every number is re-computed before it is marked ✓.
  • Weekly Insights is the agent's own brief for the latest week, read against the prior 4 weeks, all channels: headline, key stats with momentum tags, why it moved across Product · Place · People · Price, actions, a bottom line and drill questions. Contribution (pts) = a slice's change vs LY ÷ last year's total sales.
  • Investigate runs a bounded loop: each step picks the next tool from the last result, at most 6 steps, and a person approves the outcome. A reorder gap is an indicative stock gap to a weeks-of-supply target (8 weeks, or 6 when the latest week is an outlier), not an order quantity: open POs, inbound stock, lead time and size mix aren't in this data. Each step is chosen by a fixed policy from the same tool menu, so every run is repeatable.
  • Summaries here are written from rules over the same tool results; in production an LLM writes them and a checker verifies every number.

What I built

Buyers spent four to five hours every week pulling sales, inventory and plan numbers from several reports, by region and channel, to get ready for one meeting. I designed and built the first version end to end — the data model, the views, the chatbot — and worked with buyers on what belonged on the page. Buyers now catch out-of-stocks early and reorder in time.

When other regions asked for it, I rebuilt it as a framework instead of copying it five times: one shared core, one small config file per region. A new region takes about 30 minutes, and every agent the team has built since, 50+ and counting, runs on it. I still own the five buying agents and lead the design of new features: insight narratives, the chatbot, and an agentic loop that cross-checks demand against inventory.

How it works

  1. RefreshA scheduled job pulls sales, inventory and plan from the data warehouse.
  2. Shared core + region configOne code base computes every view — TY vs LY, trends, sell-through, weeks of supply; a small file per region sets currency, fiscal calendar, channels and thresholds.
  3. AlertsRules on those thresholds flag what needs action this week: items about to run out, stock to reorder, markdown risk.
  4. Insights + chatbotAn LLM writes the weekly insights and answers questions from the same governed metrics the page shows; the checks block an answer whose numbers don't match them.
  5. ChecksA checker traces every number in an answer back to the data and retries when one doesn't match; a separate QA agent re-checks the chatbot's answers in nightly checks and sends a weekly summary.
  6. Agentic loopWhen an alert fires, an agent investigates it step by step — demand, then inventory — choosing each next step from a fixed tool menu, and proposes an action for a person to approve.
  7. Feedback loopEvery answer can be rated, with a reason. Each week the agent groups the feedback and drafts fixes, the business team decides, and every fix becomes a regression test.
